# 轻小说库 · 阅读记录

本地优先的轻小说浏览与阅读记录 PWA。内置 Bangumi「轻小说」与「小说」标签合并去重后 5076 条核心数据，另从系列关联补入 7817 卷懒加载卷包，合计 12893 条；其中 788 条为仅「小说」标签的一般小说，默认隐藏。另接入 RanobeDB 扩展书目 8487 个系列（≥2 卷，31254 卷），默认隐藏、按需加载。通过 openBD 补入 3490 个单册 ISBN、906 个系列首卷 ISBN、2950 条日文版发售日，并用 RanobeDB 补系列首卷 ISBN 与缺失卷。无账号、无后端。

状态：**v1.24.1 已完成**（数据、页面、书评、统计、云同步、PWA、本地纠错、格式与藏书、多语言搜索、自动化验收 238 项 + 分片失败回归 23 项）

v1.24.1：假名与长音补全——审计发现两类日文写法仍会漏搜。①**片假名/平假名不互通**：923 条可见条目标题含片假名，用户按平假名输入（日文输入法里 `ムダに` 与 `むだに` 是同一个词）全部落空，实测 0/207；修法是归一化里加一步片假名按 `-0x60` 折平假名，长音符 `ー` 不在折叠范围（`コーヒー` 不该变成 `こひ`）。②**罗马字长音两侧不通**：构建期把 `ー` 直接删掉（`アーク`→`aku`）换来 `ramen` 能搜 `ラーメン`，但按赫本式双写元音打 `aaku`/`koohii` 的用户搜不到，实测 696 条受影响、602 条漏搜；修法是在兜底通道对罗马字多做一次长音折叠（`ou`→`o`、双写元音压缩）后比对，不挂在严格匹配上，避免中文拼音 `zhou→zho` 制造误报。同时修掉审计自身的一条空断言：长音项原判据 `/-/.test(rpyFull)` 恒为假（`rpyFull` 构建时已清洗成纯 `[a-z0-9]`），`tested` 永远为 0，而 `0===0` 让它一路显示「通过」——这条断言从写下当天起没跑过一次。新增反向验证：撤销修复后该项 FAIL（34/256），确认断言有效。审计脚本 `scripts/audit-search-coverage.mjs` 对全库 5076 条逐条验证 13 个维度，不再依赖抽样。

v1.24.0：搜索支持多写法与多语言——此前搜索只按字面匹配，实测五类查询全部落空：`ＧＲＩＤＭＡＮ`（全角）→ 0 而 `GRIDMAN` → 1；`这个勇者`（简体）→ 0 而 `這個勇者`（繁体）→ 1；`mofashizhiye`（全拼）→ 0，因为 `py` 只存首字母；`mahou`（罗马字）→ 0；作者名完全不在核心包里，未加载索引时搜人名一律 0 条且无任何提示——这是最糟的一类，用户会以为库里没有这个作者。现在：①查询与索引两侧走同一套归一化（NFC → 全角折半 → 大小写折叠 → 繁转简，后者用 `opencc-js` 的 t2cn 表，52KB gzip，前端运行时转换）；②构建期新增全拼包（4705 条）与罗马字包（4218 条，假名转写含促音双写，`プラスチック` → `purashikku`）；③作者与插图拆成独立小包（5050 条），搜索框聚焦即预取，空闲时再取全拼与罗马字；④索引未就绪时不再谎报「没有找到」，改说「正在加载作者索引」并可立即加载；⑤新增紧凑兜底——用户省略书名里的 `＆` `・` `:` `(1)` 等分隔符时（811 条可见条目属此类），严格匹配 0 条后自动放开到「忽略标点与空白」再搜一次，且不影响本来能搜到的查询。索引包不进 SW 预缓存（避免首次安装多下 152KB），`opencc` 进预缓存保证离线搜索可用。

v1.23.3：补完 v1.23.2 的漏项，分片失败处理真正收口——上一版声称 `volumes` / `rn` 也已收口，实际只加了失败标记，**没有任何 UI 读取**：`ln-volumes-failed` / `ln-rn-failed` 两个事件零监听者。实测后果：卷包失败时，豹头王传说 151 卷全部渲染成「卷 51736 —」这种**裸露 ID 加空日期**，用户会当它就是书名；扩展书目包失败时，开关已高亮成「已开启」但一本书都没多，页脚毫无说明。现在卷清单按「加载中 / 加载失败」两态提示并可重试，一条都解析不出来时不渲染裸 ID；页脚显示「扩展书目加载失败 · 重试」。顺带修掉两处关联缺陷：`updateDataHint()` 的 `!restLoaded` 分支会提前 return 吞掉扩展书目失败提示（首屏阶段点开关完全看不到）；扩展书目重试按钮原先在空结果区的委托里，而按钮渲染在页脚，点击无效。

v1.23.2：分片加载失败不再静默——`extra`（作者/插图/出版社/书系）、`ch`（子卷索引）的 `onerror` 此前只做 `resolve()`，失败与成功无法区分。extra 包失败时详情页的作者等字段会**整行不出现**，用户会以为这本书本来就没有作者。现在记录失败态并派发事件：详情页显示「字段加载失败 · 重试」，卷清单显示「卷清单加载失败 · 重试」，均可一键恢复；失败后不再自动重复请求，避免「重绘 → 又请求 → 又失败」的死循环。

v1.23.1：加载期搜索不再假报「没有找到」——首屏只加载 2026 本、其余由 `light-novels-rest.js` 后台补齐，此前在补齐前搜索会直接显示「没有找到符合条件的书目」；后台分片失败时更是无法区分。现在空结果区分「加载中 / 加载失败 / 真的没有」三态：加载中提示「已加载 N 本，完成后会自动刷新结果」，失败提示「当前只搜了首屏 N 本」并给出可点击的「重新加载」；分片到位后按当前关键词自动重绘，无需重搜。重试第三次起带时间戳绕过缓存，前两次仍走原地址以便 Service Worker 离线兜底。

## 功能

- **全库浏览**：按年份、题材、类型（轻小说 / 漫画 / 画集 / 指南）筛选；评分 / 热度 / 发售日 / 名称排序
- **系列视图**：默认隐藏系列子卷，只显示系列与独立作品；可一键显示全部系列子卷；开启「含一般小说」后纳入全部一般小说；开启「显示扩展书目」后按需加载 RanobeDB 扩展书目
- **搜索**：中文名、原名、拼音首字母、作者、本地别名；多关键词交集、`-词` 排除、标题高亮、搜索历史；支持 `作者:` `出版社:` `书系:` `年:` `分:` `题材:` 字段语法
- **我的阅读**：想读 / 在读 / 读完 / 弃读；可标记阅读 / 持有格式（纸质 / 电子 / Web / 有声）与「藏书」，按格式筛选、只看藏书；系列记录读到第几卷；系列详情提供逐卷清单（带封面缩略图），可展开勾选已读并自动汇总进度、标记下一卷；系列卡片带「子卷」入口，一键打开并展开卷清单；顶部「继续阅读」只列在读未读满的书并支持一键＋1 卷；详情内一键加减卷、读完全部；系列详情可一键加入全部子卷；读满自动标记读完并记录日期；可按最近加入 / 最近更新 / 我的评分 / 阅读进度 / 名称 / 发售日排序
- **我的书评**：1–10 分个人评分、140 字短评、1000 字笔记；输入自动暂存草稿、重开自动恢复；随记录一起导出、导入与云同步
- **阅读统计**：收藏与状态总览、年度目标进度与节奏（领先 / 落后）、我的评分分布与最常给分、藏书与格式分布、阅读打卡连续天数、历年与月度读完分布、题材偏好、常读作者、想读队列（同作者在读 / 高评分 / 短篇优先，一键开始读）

- **排序**：贝叶斯加权评分、热度、发售日、名称、卷数、我的评分

## 数据

- 扩展来源：RanobeDB（<https://ranobedb.org>，ODbL），日文原名、≥2 卷、与 Bangumi 标题去重；扩展书目无中文名与 Bangumi 评分，保留封面、卷数、起始发售日与 RanobeDB 链接
- 规模：核心 5076 条（轻小说 4288 / 一般小说 788）；系列 1394 / 单册 3682 / 子卷 2223；默认可见 2026 条；重复版本 79 条默认隐藏
- 卷包：7817 条（单行本 + 番外篇 + RanobeDB 补卷），按需加载；其中 7763 条带发售日（逐卷详情补全），展开后共 12893 条轻小说
- 统计：系列内 10040 册，按上/中/下折合 9947 故事卷
- 扩展书目：8487 个系列 / 31254 卷，默认隐藏，开关打开后按需加载
- 字段：作者 5044 条、插图 3997 条、书系 3990 条、出版社 5021 条、发售日 4978 条（含年 / 月精度）、中文名 2998 条、ISBN 3490 条、系列首卷 ISBN 906 条、日文版发售日 3918 条（任一 ISBN 覆盖 4396 条，86.6%）
- 文件：`data/light-novels-lite.js`（首屏默认可见，约 490 KB，gzip 约 160 KB）+ `data/light-novels-rest.js`（子卷 / 一般小说 / 重复版本，约 695 KB，gzip 约 175 KB，后台加载）+ `data/light-novels-ch.js`（系列子卷索引，约 96 KB，gzip 约 34 KB，打开系列详情时按需加载）+ `data/light-novels.js`（完整核心，供构建脚本使用）+ `data/light-novels-extra.js`（详情字段，约 644 KB）+ `data/light-novels-volumes.js`（卷包，约 1.48 MB，gzip 约 299 KB）+ `data/light-novels-rn.js`（扩展书目，约 2.9 MB，gzip 约 721 KB，按需加载）

- 增强：子卷缺失的书系/插图/作者/出版社/题材从父系列继承；漫画、画集、指南写入 `kind`
- 补全：系列条目缺失的书系/插图/作者/出版社从子卷共识继承，首卷日取最早子卷；Bangumi 详情补回 125 条缺失发售日，按年 / 月精度显示（`YYYY` / `YYYY-MM`），不臆造具体日
- 抓取：搜索接口单次最多 1000 条，按评分人数分区抓取后合并去重

## 开发

```bash
npm install
npm run fetch-data    # 抓取全量分页与系列关系，可中断续跑
npm run clean-series  # 用本地缓存离线重算子卷
npm run enrich-openbd # 用 openBD 补日文书系、发售日、ISBN（含系列首卷 ISBN 反查）
npm run enrich-detail # 用 Bangumi 详情补缺失日期（可中断续跑）
npm run enrich-persons # 用 Bangumi persons 接口补插图 / 作者（可中断续跑）
npm run fill-counts   # 用 RanobeDB 目录离线匹配补缺失册数与首发日（零请求）
npm run enrich-volumes # 逐卷查 Bangumi 详情补卷包发售日与封面（可中断续跑，约 7700 次请求）
npm run fill-cn       # 回查缺失中文名（RanobeDB 繁中标题 + Bangumi 同名条目，试点用 --limit）
npm run enrich-ndl    # 用 NDL Search 补 ISBN / 文库名（需本机代理，--proxy= 可清空）
npm run find-isbn     # 用 RanobeDB 补单册 / 系列首卷 ISBN（每 20 条写回，可中断续跑）
npm run fill-volumes  # 用 RanobeDB 补现有系列缺失卷（可重复运行，增量生成）
npm run build-rn      # 生成 RanobeDB 扩展书目（≥2 卷，默认隐藏）
npm run validate-ranobedb # 生成 RanobeDB 卷目对照报告
npm run check-data    # 数据校验
npm run check-deploy  # 部署边界校验（完整核心不得进入 Pages）
npm run build-pinyin  # 离线重算拼音首字母
npm run build-index   # 生成全拼 / 罗马字 / 作者搜索索引包
npm run split-shards  # 拆分分片（lite / rest / ch / 三个索引包）
npm run test-merge    # 同步合并逻辑单元测试（28 项）
npm run verify        # 无头浏览器自动化验收（238 项）
npm run check-shards  # 分片加载失败三态回归（23 项，需禁用 SW 才能模拟故障）
npm run audit-search  # 搜索覆盖率全量审计（对全库 5076 条逐条验 13 个维度，不抽样）
```

`npm run verify` 会在 `screenshots/` 输出桌面与移动端截图。push `main` 或 PR 时 GitHub Actions 自动运行 `check-data`、`test-merge`、`check-deploy`、`verify` 与 `check-shards`（Ubuntu 自带 Chrome，失败时上传截图）。

> `check-shards` 不并入 `verify` 是有意的：`extra` / `ch` / `opencc` 在 `sw.js` 的 SHELL 预缓存列表里，`au` / `pyf` / `rpy` 一旦成功取到也会被缓存，`verify` 跑到中段 Service Worker 已接管，请求走缓存优先，服务端的 503 根本拦不到，断言会假通过。该脚本改用「服务端不提供 `sw.js`」的方式确保走真实网络。

> `audit-search` 同样不并入 `verify`，理由是**判据性质不同**：`verify` 用少量样本验证「功能是否存在」，`audit-search` 对全库逐条验证「覆盖率是否完整」。抽样永远抽不到「用户会打但开发者没想到」的写法——v1.24.1 之前 `verify` 的 6 个搜索案例全绿，而假名维度实际覆盖率是 0%（0/207）。改搜索归一化、索引构建或兜底逻辑后，除了 `verify` 还应跑一次它。该脚本内置「用例数为 0 一律 FAIL」的守卫，筛不出样本时会报错而不是静默通过。

## 搜索支持的写法

查询侧与索引侧走同一套归一化（NFC → 全角折半 → 大小写折叠 → **片假名折平假名** → 繁转简），因此下列写法都能命中同一本书：

| 输入 | 命中方式 |
| --- | --- |
| `ＧＲＩＤＭＡＮ` / `GRIDMAN` | 全角折半 |
| `这个勇者` / `這個勇者` | 繁简互通（`opencc-js` t2cn，52KB gzip，运行时转换） |
| `むだに綺麗な魔法使い` / `ムダに綺麗な魔法使い` | 假名折叠（片假名按 `-0x60` 折平假名，966 条含片假名） |
| `youjiumonbuxiujian` | 全拼索引包（4705 条） |
| `tonumadeniritaikoto` | 罗马字索引包（4218 条，假名转写含促音双写） |
| `kohi` / `koohii` | 长音折叠：`ー` 在库里被删（`コーヒー`→`kohi`），双写元音写法落到兜底通道再折一次 |
| `道造` | 作者索引包（5050 条，含插图 3997 条） |
| `メタルプラスチック` | 紧凑兜底：严格匹配 0 条时忽略标点与空白再搜 |

索引包按需加载：搜索框聚焦即取作者包，空闲时再取全拼与罗马字。未就绪时结果区提示「正在加载作者索引」而非「没有找到」；失败时提示「索引加载失败」并可重试。三个索引包不进 SW 预缓存，避免首次安装多下 152KB。

## 部署

GitHub Pages：<https://xyykmkefke.github.io/light-novel-library/>

仓库根目录即站点根目录，无需构建步骤。推送后开启 `main` 分支根目录 Pages 即可。

`_config.yml` 负责部署边界：只发布运行时文件（`index.html`、`manifest.webmanifest`、`sw.js`、`icon.svg`、`icons/` 与 6 个运行时数据包），脚本、报告、截图、文档、`package*.json` 与构建输入（完整核心、`data/*.json`）全部排除出 Jekyll 站点产物。构建输入仍保留在仓库中供 `check-data`、`find-isbn` 与各构建脚本使用；`npm run check-deploy` 会在 CI 中校验排除清单、运行时文件是否被误排除，以及页面/SW 引用是否齐全。

细节见 [HANDOVER.md](./HANDOVER.md)。
